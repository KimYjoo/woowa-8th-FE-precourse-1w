# javascript-calculator-precourse

> # 과제 정의
- 문자열에서 구분자를 기준으로 숫자를 추출하고 모두 더하라
- 구분자 ⇒ 쉼표 or 콜론
- 커스텀 구분자 ⇒ 문자열 앞부분”//” 뒷부분”\n” 커스텀 구분자로 사용
- 사용자가 잘못된 값을 입력할 경우 “[ERROR]” 로 시작하는 메시지와 함께 Error 발생, 애플리케이션 종료
<br>
<br>
<br>

# 구현 전
### 제시된 요구사항 외적으로 고려한 점
##### 커스텀 구분자의 개수?
    1. 1개만 가능할때
        - 기존 방식 사용

    2. 1개 이상 가능할때
        (1) ‘//’ 와 ‘\n’ 사이에 여러 문자를 합쳐서 받기
        (2) ‘//’와 ‘\n’ 사이에 하나의 문자만 오고 여러개 작성해서 받기
        
        ⇒ 그렇다면 커스텀 구분자를 중복 입력했을 경우엔?
            1. 무시하기
            2. 에러
##### 커스텀 구분자의 제한사항?
    - 구분자는 숫자가 아니여야한다.
    - '4:,:6' 처럼 숫자 사이 여러 구분자가 입력된 경우
    - 커스텀 구분자를 정의할때 필요한 ‘/’ 및 ‘\’ 에 대한 대책이 필요 (사용은 가능)
    - ' ' 공백을 나타내는 스페이스 문자도 구분자로 사용가능
    - // 와 \n 사이에 아무것도 없을 경우엔?
        1. 무시하기
        2. 에러
##### 사용자 입력 오류의 종류?
    - 문자열에 숫자가 없을 경우
    - 기본 및 커스텀 구분자가 아닌 기호를 사용할 경우
<br><br>

### 요구사항 결론
- 문자열에서 구분자를 기준으로 숫자를 추출하고 모두 더하라
    - 구분자는 하나의 기호로 이루어져있다.
    - 숫자 사이에 여러 개의 구분자를 입력해도 하나의 구분자로 인식한다.
    - 기본 구분자 = 쉼표 ","  콜론 ":"
    - 커스텀 구분자 = 입력 문자열 앞부분에 ”//” 와 \n”의 사이에 있는 문자
        - 커스텀 구분자는 숫자일 수 없다
        - 2개 이상의 커스텀 구분자 입력 시 "//" 와 "\n" 사이에 나열
        - ' ' 공백 문자도 구분자로 포함된다.
        - 구분자 중복입력 시 하나로만 처리된다.
<br><br>

- 사용자가 잘못된 값을 입력할 경우 “[ERROR]” 로 시작하는 메시지와 함께 Error 발생, 애플리케이션 종료
    - 아무값도 입력하지 않았을 경우 
    - 입력 문자열에 숫자가 없을 경우
    - 커스텀 구분자를 등록하기 위한 문자가 틀렸을 경우
    - 커스텀 구분자가 숫자일 경우
    - 기본 및 커스텀 구분자가 아닌 문자가 존재할 경우

### 기능 요구사항 체크리스트

#### 사용자 입력
- [x] 입력 안내 메시지 `덧셈할 문자열을 입력해 주세요.`를 출력한다.<br>
- [x] 사용자가 문자열을 입력한다.<br>
<br>

#### 입력처리
- [x] 사용자 입력이 공백이면 에러를 발생시킨다.<br>
<br>

- [x] 커스텀 구분자 정의부와 일반 문자열부를 정규표현식을 통해 추출한다.<br>
<br>

- [x] 커스텀 구분자 정의부가 추출되었는지 확인한다<br>
- [x] 커스텀 구분자 내에 숫자가 있다면 에러를 발생시킨다.<br>
- [x] 내부에 있는 문자열을 문자 한개씩 나누어 구분자 집합에 추가한다.<br>
<br>

- [x] 일반 문자열부가 공백이면 에러를 발생시킨다.<br>
- [x] 일반 문자열부를 등록된 구분자로 나누어 배열로 저장한다.<br>
<br>

- [x] 나눠진 배열 중 숫자로 바꿀 수 없는 값이 있다면 에러를 발생시킨다.<br>
- [x] 배열의 문자열 요소를 숫자로 변환하여 모두 더한 결과를 저장한다.<br>
<br>

#### 결과 출력
- [x] 모든 숫자를 더한 값을 `결과 : [결과값]`와 같은 형식으로 출력한다.<br>

# 구현 후
### 미처 생각하지 못한점
- 음수 기호에 대한 처리
- 커스텀 구분자 선언부가 있지만 내부가 비었을 경우

### 추가로 적용해볼점
- 커밋 단위 기준 정하기
- 예외 상황 추가 고려 및 테스트 코드 추가
- 코드 리팩토링 방법론
    <br>
    > 해당 과정은 chatGPT에 초안 코드를 보여주며 적용시킬만한 리팩토링 방법론을 요청한 결과를 정리한 것 입니다.
    <br>
    #### 리팩토링 방법론
    - Rename: 변수/함수/매개변수를 더 의미 있는 이름으로 변경.

    - Extract Variable: 길거나 중첩된 식 일부를 중간 변수로 분리(의도 드러내기).

    - Inline Variable/Function: 쓸모없는 중간 단계 제거(잡음 줄이기).

    - Extract Function: 블록을 작은 함수로 빼내고, 호출부만 남김.

    - Introduce Guard Clauses: 중첩 if 대신 초기에 빨리 반환(예외/엣지 먼저).

    - Split Variable: 여러 의미로 재사용되는 변수 → 목적별로 분리.

    - Replace Magic Number/String with Constant: 상수화로 의미 문서화.

    - Decompose Conditional: 복잡한 조건식을 서술적 함수들로 분해.

    - Split Loop: 한 루프에서 여러 일을 하면 → 루프를 목적별로 쪼개기.

    - Replace Temp with Query: 임시값 대신 함수 호출로 의존성/순서 줄이기.

    - Move Statements: 관련 있는 코드끼리 가까이 모으기(초미세 정리).

    - Encapsulate Condition/Collection: 조건/컬렉션 조작을 함수로 감싸 부작용 제한.

    #### 리팩토링 적용 템플릿
    1. 이름 손보기 - 변수의 이름을 의도가 들어나도록 수정
    2. Guard로 분기 얕게 만들기 - 중첩된 if 문을 제거하고, 잘못된 입력은 일찍 탈출하게 만든다.
    3. Extract Function으로 의미 단위 분해 - 한 가지 일만 하는 함수로 쪼개서 구조를 드러낸다.
    4. 상수화/유틸 분리 - 하드 코딩된 값을 쓰지 않고 이름 있는 상수로 사용
    5. 부작용(콘솔의 I/O을 다루는 부분)을 껍질로 밀어내기 - 콘솔에 입력과 출력하는 부분과 같은 부작용(에러)가 발생할 여지가 있는 부분을 나눈다.
    6. 순수 함수화 - 단순 입력 출력 형태의 로직을 구성한다.
